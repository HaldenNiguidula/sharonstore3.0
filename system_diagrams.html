  • Research Design: Descriptive Research Design with Purposive and Convenient sampling.

Process Execution Details

  • Process 4.0 (POS Checkout): Performs dual verification: reads barcode, verifies available stock > 0, enforces atomic database transaction, inserts transaction code TXN-YYYYMMDD-XXXX, and decrements stock_qty.
  • Process 6.0 (Demand Forecasting): Queries transaction line items grouped by month, applies Single Moving Average (SMA) and Weighted Moving Average (WMA), and outputs the net restocking recommendation: $\max(0, \hat{Y} - S_{current})$.

Database Isolation & Security

  • Audit Automation: Processes 1.0, 3.0, 4.0, and 8.0 write asynchronously to tbl_audit_logs recording client IP address, action code, and target user ID.
  • Daily PIN Isolation: tbl_settings stores a daily generated manager PIN (refreshed at midnight via getDailyManagerPIN()) preventing unauthorized drawer open/close without owner validation.

Key Constraints & Normalization

  • Foreign Key Integrity: tbl_inventory.category_id ON UPDATE CASCADE; tbl_transaction_details.transaction_id ON DELETE CASCADE ON UPDATE CASCADE.
  • Atomic Shift Tracking: tbl_transactions.shift_id links each checkout to the cashier's active shift float for instant drawer reconciliation.
  • Unique Enforcements: uq_barcode on tbl_inventory prevents duplicate barcodes; uq_txn_code ensures uniqueness across daily transactions.

Quantitative Field Precision

  • Monetary Fields: decimal(10,2) used on all prices, tendered cash, and totals to completely eliminate floating-point rounding errors in retail currency.
  • Fractional Quantities: quantity and stock_qty defined as decimal(10,2) to support non-discrete consumer items sold in kilograms (e.g. sugar, rice).

Cash Reconciliation Mathematics

Cash Drawer Reconciliation Formula
Expected Cash = Starting Float + Σ(Cash Sales During Shift)
Short / Over = Actual Cash Counted − Expected Cash
Where Short < 0 indicates a register cash shortage, and Over > 0 indicates an overage. Recorded in tbl_shifts.short_over.

Atomic Checkout Safeguards

  • Race Condition Prevention: handleCompleteSale() executes within a PDO transaction wrapper (beginTransaction and commit) ensuring that both transaction details and stock decrements are atomic.
  • Negative Stock Lockdown: If two cashiers attempt to ring up the last unit simultaneously, row-level verification halts the second sale with HTTP 409 Conflict.

Specific Administrative Subsystems

  • BI Dashboard: Real-time KPIs, dynamic date filters (7d/30d/YTD), 30-day sales trend line charts, category distribution doughnut charts, and fast-moving FMCG alerts.
  • Inventory Operations: Add new items with barcode generation, edit selling prices, restock deliveries, write off damaged/expired stock, manage categories, and soft-delete (is_active=0).
  • Demand Forecasting: Run SMA and WMA models across 3, 6, or 12 month lookback horizons to calculate projected demand ($\hat{Y}$) and suggested restocking gaps.
  • Shift Governance: Review cash discrepancy reports, inspect starting floats vs actual cash, rotate daily manager PINs, and force-close abandoned cashier shifts.

Governance, Voiding & Disaster Recovery

  • Sale Voiding Authority: Admins can void erroneous sales within 24 hours via handleVoidTransaction(), atomically restoring stock to inventory and recording a VOID_TRANSACTION audit event.
  • User Security: Bcrypt password hashing, role-based session isolation, and non-destructive deactivation (preserving historical cashier links).
  • Database Backups: Automated mysqldump execution with standalone PHP PDO fallback creating portable, timestamped .sql files in backups/.

Forecasting Engine Math Flow

1. Simple Moving Average (SMA)
SMA = (Σ Qty_sold) / n
Where n is 3, 6, or 12 historical months. Gives equal weight to each month.
2. Weighted Moving Average (WMA)
WMA = Σ(w_i × Qty_i) / Σ w_i
Where weight $w_i = i + 1$ (1 to $n$), prioritizing recent consumer demand trends in the Pampang Public Market.

Restock Recommendation Formula

Recommended Restock Quantity
Restock_Qty = max(0, Predicted_Qty − Current_Stock_Qty)
If current stock exceeds forecasted demand, restock recommendation evaluates to 0, completely preventing retail overstocking and financial spoilage.
