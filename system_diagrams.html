Pampang Public Market, Angeles City, Pampanga | BSIS Capstone Project

Store App
Engineering & Capstone Documentation

A Web-Based Inventory and Sales Forecasting System with Business Intelligence Dashboard

This comprehensive document contains all architectural, structural, data flow, behavioral, and database design diagrams for Sharon Store 3.0. Designed specifically to resolve pen-and-paper operational bottlenecks, stockouts, and spoilage at the Pampang Public Market locale via barcode-integrated POS, moving average forecasting (SMA & WMA), and real-time executive analytics.

Inputs & Framework Foundations

  • Research Design: Descriptive research with convenience sampling for retail participants and purposive sampling for IT experts, as stated in the current paper.
  • Evaluation Sample: 52 retail participants and 3 IT experts; 55 respondents in total. The current paper does not use Slovin's formula.
  • SDG Alignment: Direct contribution to UN SDG 9 (Technology Upgrade for MSMEs) and SDG 12 (Reduction of retail spoilage and food waste).

Operational Deliverables & Scope

  • Included: Barcode scanning or search, atomic stock deductions, moving-average forecasts, shift cash reconciliation, audit trail, PHP/PDO SQL backup and restore, and optional Google Drive upload.
  • Explicitly Excluded: BIR tax filing, payroll, online customer commerce/delivery and direct proprietary cash-drawer or printer control. Receipt printing uses the browser print dialog.

Process Execution Details

  • Process 4.0 (POS Checkout): Performs dual verification: reads barcode, verifies available stock > 0, enforces atomic database transaction, inserts transaction code TXN-YYYYMMDD-XXXX, and decrements stock_qty.
  • Process 6.0 (Demand Forecasting): Queries transaction line items grouped by month, applies Single Moving Average (SMA) and Weighted Moving Average (WMA), and outputs the net restocking recommendation: $\max(0, \hat{Y} - S_{current})$.

Database Isolation & Security

  • Audit Automation: Processes 1.0, 3.0, 4.0, and 8.0 write asynchronously to tbl_audit_logs recording client IP address, action code, and target user ID.
  • Daily PIN Isolation: tbl_settings stores a daily generated manager PIN (refreshed at midnight via getDailyManagerPIN()) preventing unauthorized drawer open/close without owner validation.

Key Constraints & Normalization

  • Physical and Logical Links: Dotted ERD links for shifts are application associations, not foreign keys in the supplied SQL dump. Runtime schema initialization can make transaction user IDs and shift cashier IDs nullable. tbl_sessions.data stores serialized session content and has no user foreign key. Enforced Keys: tbl_inventory.category_id ON UPDATE CASCADE; tbl_transaction_details.transaction_id ON DELETE CASCADE ON UPDATE CASCADE.
  • Atomic Shift Tracking: tbl_transactions.shift_id links cashier checkout to an active shift; admin sales may have no shift for instant drawer reconciliation.
  • Unique Enforcements: uq_barcode on tbl_inventory prevents duplicate barcodes; uq_txn_code ensures uniqueness across daily transactions.

Quantitative Field Precision

  • Monetary Fields: decimal(10,2) used on all prices, tendered cash, and totals for database precision; application calculations still use PHP floating-point arithmetic and rounding.
  • Fractional Quantities: quantity and stock_qty defined as decimal(10,2) to support non-discrete consumer items sold in kilograms (e.g. sugar, rice).

Cash Drawer Reconciliation

Cash Drawer Balance Formula
Expected Cash = Starting Float + Σ(Cash Sales During Shift)
Discrepancy (Over / Short) = Counted Cash − Expected Cash
A negative discrepancy indicates a cash shortage in the drawer, while a positive value indicates an overage.

Cashier Access & POS Checkout Rules

  • Shift-Gated Stock Monitoring: Cashiers require an open, manager-authorized shift to access the stock-monitoring lists, statistics and expiry alerts.
  • Locked POS Register Workspace: Cashier checkout and stock monitoring are locked without an open shift; it strictly requires a daily Manager PIN and starting cash float to unlock the cash drawer and begin ringing up sales.
  • Automated Stock Deduction: Automatically decrements product quantities and prints customer receipts upon completing customer sales.

Inventory & Wholesale Suppliers

  • Catalog Maintenance: Add new items, update selling prices, record delivery restocks or damage write-offs, and organize categories.
  • Supplier Directory: Maintain wholesale vendor profiles, contact information, and a standalone supplier directory; products have no supplier foreign key.
  • Stock Monitoring: Real-time lookup of stock levels, minimum safety thresholds, and 30-day expiration alerts.

Analytics & System Administration

  • BI Dashboard & Reports: Track gross revenue, COGS, and profit margin % with exportable daily/weekly/monthly breakdowns.
  • Demand Forecasting: Calculate projected sales demand and suggested replenishment order quantities using moving average models.
  • User Security & Backups: Manage staff user accounts with role-based access control and generate one-click database backups.

Forecasting Engine Math Flow

1. Simple Moving Average (SMA)
SMA = (Σ Qty_sold) / n
The window contains 3, 6 or 12 consecutive calendar months ending in the current month. Zero-sales months count as zero; the current month may be incomplete.
2. Weighted Moving Average (WMA)
WMA = Σ(w_i × Qty_i) / Σ w_i
Where weight $w_i = i + 1$ (1 to $n$), prioritizing recent consumer demand trends in the Pampang Public Market.

Restock Recommendation Formula

Recommended Restock Quantity
Restock_Qty = max(0, Predicted_Qty − Current_Stock_Qty)
If current stock exceeds forecasted demand, restock recommendation evaluates to 0, avoiding a negative replenishment suggestion; forecasts cannot guarantee prevention of overstocking or spoilage.

Low-Stock Trigger Parameters

  • Healthy State: stock_qty > low_stock_threshold. Displayed with an emerald green badge.
  • Low-Stock Warning: 0 < stock_qty <= low_stock_threshold. Displayed with an amber warning badge on POS and Dashboard.
  • Out of Stock: stock_qty <= 0. POS prevents ringing up with instant error notification.

Expiration Monitoring Thresholds

  • Expiring Soon State: Alert queries select dated active products with expiry_date <= DATE_ADD(CURDATE(), INTERVAL 30 DAY), including overdue products. Inventory lists classify expiry on or before today as expired.
  • Soft Delete Architecture: Items are never physically dropped from MySQL; is_active = 0 preserves referential integrity for historical transaction reports.

Directory Topology

  • Root Directory: Contains main page entry points, including pos.php, dashboard.php, and inventory.php.
  • /api/ Directory: Contains all JSON-responding RESTful controller scripts handling async requests from Vanilla JS Fetch calls.
  • /includes/ Directory: Contains security enforcement scripts, PDO singletons, and audit helper functions.

Engineering Design Decisions

  • Vanilla JavaScript ES6: Avoids heavy bloated frontend node-module frameworks, ensuring ultra-fast load times on low-power store market terminals.
  • PDO Prepared Statements: Prepared parameters are used for data values; dynamically selected identifiers and numeric query fragments require validation. This is not a guarantee against all injection risks.
